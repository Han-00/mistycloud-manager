# 账号大师 Pro · Web UI 执行方案

> 方向：深色控制台布局 + Web 前端实现（A + C 组合）
> 目标：先交付可交互高保真界面（模拟数据），再对接 Python 后端替换现有 customtkinter 界面

---

## 1. 技术路线

| 层 | 选型 | 说明 |
|---|---|---|
| 界面 | 纯 HTML + CSS + 原生 JS（零依赖） | 单页应用，四个视图：仪表盘 / 账号库 / 日志 / 设置 |
| 壳 | pywebview（第二阶段接入） | Python 后端零改动，通过 JS 桥通信 |
| 数据桥 | `bridge.js` 抽象层 | 有 `window.pywebview.api` 走真后端，否则走内置模拟数据；两个阶段用同一份界面代码 |
| 预览 | `npm run dev`（自带零依赖静态服务器 server.js） | 浏览器直接预览，无需安装任何依赖 |

**为什么不上一开始就 pywebview**：界面先在高保真原型阶段打磨好，后端对接只是替换 bridge 层，界面代码一行不用改。

## 3. 设计系统

**场景设定**：用户常在暗光环境盯盘式管理账号，需要一眼判断链路健康度、一键完成换号 → 深色主题为正确选择。

**色彩策略**：克制型（Restrained）。深色中性底 + 单一品牌蓝，仅用于主操作、选中态、状态指示。沿用现有品牌蓝（#2f6fed 家族），OKLCH 定义：

| Token | 值（约） | 用途 |
|---|---|---|
| `--bg` | oklch(0.17 0.015 265) | 主区底色 |
| `--bg-side` | oklch(0.15 0.014 265) | 侧栏（次中性层） |
| `--surface` | oklch(0.205 0.016 265) | 卡片/面板 |
| `--surface-2` | oklch(0.23 0.018 265) | 次级按钮、悬浮态 |
| `--border` | oklch(0.30 0.02 265) | 分隔线 |
| `--text` / `--muted` | oklch(0.94) / oklch(0.68) | 主/次文字（对比度 ≥ 4.5:1） |
| `--accent` | oklch(0.65 0.18 262) | 品牌蓝：主按钮、选中态 |
| `--ok` / `--warn` / `--err` | 绿 / 琥珀 / 红 | 链路状态、日志级别 |

**字体**：系统字体栈（Inter → system-ui），邮箱 / IP / 数字用等宽字体；固定 rem 字阶（不用流式），比例 1.125–1.2。

**形状**：卡片圆角 12–14px，按钮 10px，标签全圆角；边框或阴影二选一（不叠加）。

**动效**：150–250ms ease-out，只表达状态（切换 loading、状态灯呼吸、toast 反馈、日志滚动）；全局支持 `prefers-reduced-motion`。

## 4. 页面结构

### 仪表盘（默认页）
1. **状态横幅**：当前账号（等宽大号）+ 在用胶囊 ｜ 链路状态呼吸灯（绿/黄/红）+ IP + 延迟 + 检查时间 ｜ 右侧大号「立即换号」主按钮（点击变 loading，完成后 toast）
2. **指标条**（一条四格，非卡片堆砌）：流量剩余（大数字 + 细进度条 + 已用/总量）· 有效期（秒级倒计时）· 代理链路（IP + 延迟）· 账号池（在用/备用数）
3. **账号库预览表**：邮箱（等宽）· 状态胶囊 · 剩余时长内嵌迷你条形图 · 行 hover 浮现「切换」操作 · 复选 + 工具栏（补号 / 刷新状态 / 删除选中）
4. **日志抽屉**：底部可折叠，默认收起，新日志红点提示，级别着色，可清空

### 账号库（整页）
完整表格（更多行）+ 搜索过滤 + 同一套工具栏与行操作

### 日志（整页）
级别筛选（全部/信息/警告/错误）+ 自动滚动开关 + 清空 + 导出

### 设置（整页）
自动换号开关 · 换号间隔 · 流量告警阈值 · 代理端口 · 日志级别；「保存设置」主按钮 + 「恢复默认」次级按钮，保存后 toast 确认

## 5. 交互清单（原型阶段全部可点）

- 侧栏导航切换视图，当前项高亮
- 立即换号：按钮 loading → 1.4s 后轮换账号、追加日志、toast 成功
- 有效期倒计时每秒跳动；流量进度条动画
- 表格行选中 / hover 操作 / 切换到所选
- 日志抽屉展开收起、新条目红点、自动滚动
- Toast 通知系统（右下，成功/错误两态）
- 设置保存即时反馈

## 6. 后端对接预留（第二阶段）

`bridge.js` 定义与后端对齐的 API 面，与现有 Python 模块一一对应：

| JS 方法 | 对应 Python |
|---|---|
| `getState()` | stats.py / account_pool.py 状态汇总 |
| `switchNow()` | switcher.py 立即换号 |
| `switchTo(email)` | switcher.py 指定切换 |
| `addAccount()` / `removeAccounts(emails)` | account_pool.py |
| `refreshStatus()` | monitor.py |
| `getLogs()` / `clearLogs()` | logger.py |
| `getSettings()` / `saveSettings(s)` | config.py |

第二阶段只需：写一个 `main_webui.py` 启动器，把这些方法暴露给 pywebview，界面零改动。
