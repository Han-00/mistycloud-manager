# 账号大师：功能与场景扩展路线图

评估日期：2026-10-02。版本号为规划建议，并非已发布版本。

推荐下一版先做「分流规则中心 + 场景模式」，让学习、开发和日常浏览有各自可保存的配置；随后扩展手机与桌面联动、节点管理与外部订阅。这个顺序基于现有代码的复用程度和用户可感知的收益，属于产品判断，开发成本为相对估计。

## 当前能力与边界

源码已具备账号注册与备用池、自动换号、v2ray 进程管理、系统代理、国内域名直连、托盘、自启、飞书通知、流量热力图和可用率统计。下一版不必重复建设这些能力。

当前存在可用于扩展的具体底座：

| 已核实的实现 | 扩展机会 | 源码依据 |
|---|---|---|
| 内置直连域名与用户追加域名合并，生成引擎路由；Web 设置未暴露规则编辑 | 分流规则中心、规则组、场景配置 | `config.py:35`、`config.py:96`、`v2ray_engine.py:229`、`webui/index.html:169` |
| 订阅解析返回第一个有效 VMess 节点，切换流程只使用单个节点 | 节点列表、手动选线、同账号线路故障切换 | `cloud_api.py:204`、`switcher.py:159` |
| 异常消耗模块能够分析小时桶和关联换号事件；对主入口、三个 UI、监控和 Web 资源的静态引用检索未发现调用 | 异常时段提示、消耗分析与预算提醒 | `anomaly.py:88`、`stats.py:130`；调用情况依据引用检索 |

以上是静态检查结果；没有查询真实订阅、账号或运行日志，没有执行主程序或实机测试。

## 建议版本顺序

### v2.1：场景模式与分流规则中心

核心体验：输入网站域名，选择直连或代理；保存为自己的「学习」「开发」「日常」方案，并从主界面切换。

实施范围：

1. 增加规则数据模型，区分内置规则、用户规则和禁用的内置规则。当前「内置 + 追加」语义无法表达删除内置域名或强制某域名走代理，需要兼容迁移旧配置。
2. 提供规则增删、分组和导入导出；明确优先级与默认出站策略。输入域名后展示按当前规则预计匹配哪一条，此预览不等同于真实连接的路由证明。
3. 增加场景方案，保存规则组与运行策略。账号密码和通知密钥仍保存在各自配置中，方案导出只包含可分享的场景参数。
4. 应用配置时先验证，串行执行引擎变更；应用失败应恢复旧配置并显示结果。现有系统代理例外与引擎分流两层都必须同步。

验收重点：

- 可以新增直连域名，也可以覆盖或禁用某条内置直连规则；重启后保留结果。
- 场景切换过程中，不与换号、自愈同时写引擎配置；失败时旧方案仍可用。
- 用可控目标验证直连和代理出口，验证子域名、重复规则及冲突优先级。
- 将旧 `settings.json` 迁移后，原来的规则和默认行为保持有效；导出方案不包含凭据。

这里最值得先落地的是规则模型与编辑入口。场景模式复用它，避免两套功能各自维护规则。

### v2.2：跨设备交接与工具接入

核心体验：手机注册成功后，电脑可以接收并验证账号；终端或支持代理的工具可以直接使用当前电脑代理。

实施范围：

- 桌面增加账号导入入口，校验登录、订阅和服务端到期时间，按邮箱去重。导入应保留原注册时间，不能直接以导入时间重置本地生命周期；当前 `AccountPool.add()` 需要扩展这点。
- 先定义版本化导出格式与桌面导入路径，避免把 Android 与桌面存储文件直接互拷。传输凭据时提供加密与明确的接收确认；二维码更适合短时配对信息。
- Android 当前产品定义是单功能注册器。本阶段仍围绕账号交接展开；完整 VPN 客户端是独立的较大产品范围。
- 工具接入页显示实际监听地址和测试结果，生成临时会话配置。不同工具是否支持环境变量、HTTP 或 SOCKS，需分别验证。

验收重点：重复导入不覆盖有效记录的时间信息；过期或无效账号不会成为备用候选；交接结束后临时传输失效；工具接入设置只作用于明确选择的会话。

### v2.3：节点管理与订阅来源扩展

核心体验：同一个账号可选择不同线路；用户也可管理自己持有的独立订阅。

实施范围：

- 将订阅解析从单节点扩展为节点列表，先覆盖现有 VMess 格式，再按实际需求支持更多协议。
- 区分「换线路」和「换账号」：换线路不淘汰账号，不触发自动注册。
- 增加节点备注、手动锁定与连接状态记录。自动选线先作为可选策略，避免频繁改变出口。
- 独立订阅作为新的来源类型，有自己的刷新与到期状态；不能套用临时账号的自动注册和淘汰逻辑。

是否能为现有 MistyCloud 账号带来多线路收益尚未核实：本次没有读取真实订阅。如果服务端只下发一个节点，节点列表的主要收益来自外部订阅。

### 穿插迭代：消耗分析与预算提醒

先把已有 `anomaly.detect()` 接入仪表盘，显示消耗异常的小时、历史基线和账号关联，并区分直接关联与推断。再增加预算提醒与告警去重。

当前小时统计只保留约八天，月度预算需要扩展持久化历史。当前订阅配额采样也不等同于本机实时网速；速度曲线需要读取引擎统计，并区分代理与直连出站。现有数据不足以回答「哪个进程最耗流量」。

## 更大的场景：多个独立代理会话

适用场景：两个支持显式配置代理的工具分别连接不同端口，独立选择账号或节点，其中一个切换不影响另一个。

引擎类的文档已经描述了可扩展多实例，但主应用编排与账号生命周期仍围绕单会话运行。这是后续大版本候选：需要会话级账号租用、端口和工作目录隔离、每会话监控、独立流量统计，以及引擎启停权限归属。当前单 active 与淘汰旧号的语义不能直接复用为多会话语义。即使开出多个端口，底层线路、账号和服务商限制仍决定实际隔离程度。

## 技术可行性来源

- [V2Fly 路由文档](https://www.v2fly.org/config/routing.html)：规则按顺序匹配，支持域名和入站标识等条件，可选择出站。规则编辑与场景分流有引擎层基础。
- [V2Fly 统计文档](https://www.v2fly.org/config/service/stats.html)：可统计指定入站、出站的上下行字节，须同时启用对应策略，可用于后续代理/直连统计。
- [V2Fly 连接观测文档](https://www.v2fly.org/config/observatory.html)：提供出站连接观测能力，是自动选线的候选实现之一。
- [Android VPN 官方文档](https://developer.android.com/develop/connectivity/vpn)：完整 VPN 涉及 VpnService、用户授权及隧道生命周期，应单独评估实现范围。

官方文档说明的是引擎和平台能力。本次未核实包内 v2ray 的版本与相关功能兼容性，实施时需要针对实际引擎验证配置，不能直接认定可用。

本文件仅新增产品规划；源码、现有账号、代理配置和 Android 产品实现均未修改。开发与运行验收尚未执行。
